# PGH-FAIL-0027 — Bridge Edge-Equivalent Internalizations

## Failure class

A primitive bridge internalization fails formal candidacy when its apparently compact representation is information-equivalent to the component context-record edge structure whose generation it is later supposed to explain.

## Direct edge control

Adding

\[
e_{c,r}:X_c\to Y_r
\]

for every typed pair directly enters the cross-type edge family.

No later hom-existence result reproducing those edges can receive explanatory credit.

## Product-packaging control

For a finite typed fiber, adding

\[
m:X\to\prod_iY_i
\]

may use one displayed morphism, but the product universal property gives

\[
Hom(X,\prod_iY_i)\cong\prod_iHom(X,Y_i).
\]

Thus `m` is equivalent data to the full component-arrow tuple.

```text
SYMBOL_COUNT_REDUCTION = POSSIBLE
INFORMATION_REDUCTION = NO
EXPLANATORY_COMPRESSION = NO
```

This is the bridge-level analogue of the project's earlier warning that arbitrary structures can be made short by adding a privileged primitive name.

## Target-directed type aggregation

Even a formally non-edge-equivalent aggregate process fails if its output object or grouping is chosen after observing the desired response partition.

For example, if the coproduct fibers are reconstructed exactly from empirically allowed-response classes, the selectivity has entered through the typed anchor/grouping rather than being generated by the bridge.

## What survives

The coproduct aggregate-output candidate survives this particular failure because a map into a coproduct is not generally equivalent to a tuple of component maps and because the same typed fiber supports multiple response laws.

This survival establishes formal candidacy only.
